# 常见问题与故障排查

## 图库是空的

**现象：** 侧边栏提示没有找到任何卷。

检查 `raw/` 下的文件夹结构：

```text
raw/<volume>/<language-dir>/<chapter>/001.jpg
```

常见原因：

- 卷文件夹存在，但语言文件夹未被识别。使用卷设置进行映射，或把它重命名为 `ja`、`zh` 或 `en`（别名列在[图库](/zh/guide/gallery)中）。
- 章文件夹直接位于卷之下（`raw/<volume>/001.jpg`）。必须有一层语言目录。
- 桌面应用的数据目录指向了别处。按 `Ctrl+Shift+D` 选择正确的文件夹，或设置 `MANGA_DATA_DIR`。

## 某一页缺少某种语言

**现象：** 某页只显示 `JA` 和 `ZH`；`EN` 被禁用。

页面按排序后的索引配对。如果该章中的英文文件少一个，最后一页就没有英文图片。页面警告会指出缺失的语言和页码。补上该文件或删掉多余的页面。

如果数量一致但配对错误，请检查文件名：开头的数字与排序位置不一致会触发警告。重命名文件，让自然排序符合预期顺序。

## 文件名看起来没问题，但页面顺序乱了

排序是**自然排序**：连续数字按数值比较，因此 `2.jpg` 排在 `10.jpg` 之前。它不是按字节的字典序。如果文件没有开头数字，它可能会排在带数字的文件之前。请统一加上页码前缀，例如 `001.jpg`、`002.jpg`。

## 分格检测不准确

- **左右两侧的竖条被忽略了。** 这是有意为之：窄的边缘竖条（通常是 *あらすじ* 或作者注）会被过滤，以免成为误判的分格。合法的边缘分格请手动绘制。
- **跨页大图** 常常产生一个大分格加上若干碎片。选中碎片并**合并**。
- **非常小或非常细的框** 会作为噪声被过滤。如果它们是真实分格，请手动添加。
- **WebP 页面不会被解码** 用于检测。如果需要自动检测，请转换为 JPEG/PNG。
- **固定的杂志版式** 更适合用[布局模板](/zh/extending)，而不是检测。

修正分格之后，除非你愿意丢失手动绘制的框，否则不要重新运行自动检测。

## 导出的 HTML 里没有图片

**文件夹模式（默认）：** HTML 引用同级的 `<name>.files/` 目录。请把 `.html` 文件**和** `.files` 文件夹一起复制，并保持它们的相对位置。只打开 HTML，或把它移出该文件夹，都会导致图片失效。

**单文件模式：** 图片已内嵌，因此只需要 HTML 文件。代价是体积——整章可能达到几十兆字节。

## 找不到原始图片

**现象：** `.mnproj` 导入报告图片缺失，或某页显示 404 占位图。

- **引用模式的项目** 存储的是路径，而不是图片。如果图片被移动，请重新导入并设置**重新关联目录**。导入器先按 SHA-1 匹配，再按文件名匹配，并优先选择包含卷名和章名的文件夹。
- **打包模式的项目** 把图片放在 `assets/` 中。缺少资源意味着项目包不完整；请重新导出。
- 如果图片仍然存在但被重命名了，请把它们放入符合预期结构的文件夹，然后使用重新关联。

## 我的编辑丢失了

检查工具栏中的保存模式：

- **自动** 会以防抖方式保存。
- **确认** 需要点击保存勾选。带着未保存的改动离开会显示浏览器警告，但崩溃或强制关闭仍可能丢失最后的编辑。

同时确认你打开的是同一页：URL hash 包含卷、章、页码和视图。在另一个数据目录上打开应用会显示不同的图库。

## 应用模板后分格笔记消失了

当分格模板（或重新检测）改变了分格数量时，分格级笔记无法被可靠映射，因此会被丢弃。页面级笔记始终保留。如果数量不变，笔记会按阅读顺序重新映射。

为避免这种情况，在把模板应用到整章之前先导出一个备份。

## 端口 5173 已被占用

Vite 配置为 `strictPort: false`，因此它会转移到下一个空闲端口。请查看终端输出中的实际 URL。文档站点使用 `5174`。

## 如何备份所有内容？

- **备份 ZIP** —— 整个 `data/`（JSON、模板、预设），不包括缩略图缓存。
- **`.mnproj`** —— 项目包，可含图片也可不含图片。
- **复制文件夹** —— `raw/` 是你的图片；`data/` 是你的工作成果；`exports/` 可以重新生成。

参见[远程存储与备份](/zh/remote-backup)。

## 遇到错误码怎么办？

服务端与 CLI 会返回 `ERR_*` / `WARN_*` / `STATUS_*` 稳定错误码，而 `error` / `message` 文本会按请求语言本地化。完整错误码与 HTTP 契约见[服务端与 CLI 消息码](/server/error-codes)（英文页面，以英文为准）。

## 缩略图看起来过期或损坏

删除 `data/cache/thumbs/`。它是缓存，会按需重建。备份和项目包本来就不包含它。

## 搜索笔记没有结果

- 搜索覆盖笔记正文、标签和来源。请检查当前生效的卷/章/标签/来源筛选。
- 笔记必须被**保存**后才会被索引。在确认模式下，未保存的编辑还不在磁盘上。
- 总览会索引页面 JSON；保存失败的页面没有可搜索的笔记。

## 桌面应用启动了，但显示的是旧页面集

桌面窗口可能使用了与仓库不同的数据目录。检查窗口标题（其中包含数据路径），然后按 `Ctrl+Shift+D` 切换。`MANGA_DATA_DIR` 会覆盖已保存的设置。

## 为什么不能导出 PDF 或 Word？

只实现了 HTML 和 PNG。PDF、`.docx` 和词表都是<Badge type="warning" text="计划中" />。作为变通方法，可以在浏览器中打开导出的 HTML，并使用 **打印 → 另存为 PDF**；该 HTML 带有分页样式，会按页断开并避免拆分分格或笔记。

## 为什么不能创建分格分组？

页面 JSON 支持 `group` 对象，导入和导出也会保留它们，但目前还没有分组编辑界面（<Badge type="warning" text="计划中" />）。你可以手动编辑 JSON；读取时会进行规范化与校验。矢量**标注**已经实现：切格工作台提供箭头、矩形、椭圆、高亮、自由画笔、文本、徽标和马赛克工具。

## 它会把我的数据发送到任何地方吗？

默认不会。服务器监听 `127.0.0.1`，不配置远端目标时不会上传任何内容。有两类操作会发起外部请求：笔记来源中可选的“获取页面标题”（请求你输入的 URL，超时 5 秒），以及你主动添加的 WebDAV / 网络存储目标（按需拉取图片、上传备份）。未配置存储目标时，所有数据都留在本机。

## 旧的页面 JSON 打不开

手改过的或较旧的 JSON 在读取时会被规范化：缺失的 id 会被生成，矩形会被限制范围，无效的枚举值会回退到默认值，悬空的分组引用会被移除。如果文件根本不是有效的 JSON，应用会认为该页没有数据并重新检测——这会在保存时覆盖该文件。如果发生这种情况，请从备份恢复。

## 还有其他问题

寻求帮助前，请先收集这些信息：

1. 启动 `npm run dev` 或 `npm run desktop` 的终端输出。
2. 确切的页面路径（`data/pages/<volume>/<chapter>/<index>.json`）。
3. 删除 `data/cache/thumbs/` 后问题是否仍然复现。
4. 如果问题与检测相关，提供 `node scripts/manga-cli.ts report` 的输出。
