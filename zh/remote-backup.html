远程存储与备份 ​

目前已有的能力 ​

本地磁盘是默认选择：KomaYomi 从 raw/ 读取图片，把标注写入 data/，把生成的文件写入 exports/。在此之上，服务器还支持通过 WebDAV 或挂载的 / SMB 网络共享来配置远程图片源和远程备份目标，相关设置位于数据工具 → 存储，保存在 data/storage.json（schemaVersion: 1）。

此外还有两道本地安全网，都便于迁移。

远程图片源（WebDAV / 网络驱动器） ​

类型为 webdav 或 network 的存储目标可以设为 rawSource。

  • 结构同步 —— 同步 会遍历远程目录树，把其中的文件夹镜像到 raw/，用零字节的占位文件表示（最多 20,000 个图片文件）。已有的图库扫描器和命名规则继续有效；占位文件标明了哪些页面存在。
  • 按需拉取 —— 图片字节会在页面或缩略图首次打开时下载，而不是在同步时下载。已拉取的文件缓存在 data/cache/remote/files/ 下，以“提供方 id + 相对路径”的 SHA-1 作为寻址键。
  • LRU 缓存 —— 缓存上限由 cacheLimitMb 控制（默认 512 MB）。每次写入后，服务器会按最近最少使用顺序清理文件，直到占用低于上限的 90%。缓存可以在存储界面中清空。
  • 离线时 —— 已在缓存中的页面仍可阅读。未缓存的图片会返回 HTTP 503 和错误码 ERR_REMOTE_UNAVAILABLE；缩略图拉取失败会返回 502 ERR_THUMB_FETCH_FAILED。图库会继续列出这些页面，而不是卡住或静默丢弃。
  • 凭据 —— 用户名保存在 storage.json 中；密码使用 AES-256-GCM 加密后保存在 data/secrets.json.enc，密钥是每次安装生成的 data/.secret.key（权限 0600）。API 只会报告 hasSecret，永远不会返回密码。这是可移植的兜底方案，而不是操作系统钥匙串；任何人把整个 data 文件夹连同 .secret.key 一起复制走，都能解密。
  • WebDAV 细节 —— Basic 认证，PROPFIND 用于列目录/查询状态，GET 用于读取，PUT 用于写入，请求超时 10 秒。只读目标仍可作为图片源使用，但会拒绝上传（ERR_STORAGE_READONLY）。

备份 ZIP ​

  • 为 data/ 创建 ZIP，每个条目都以 data/ 为前缀，并带有 data/.backup-meta.json 标记文件。
  • 排除缩略图缓存以及 .tmp / .log 文件。
  • 文件写入 exports/ 并提供下载。如果选择了备份目标，同一个 ZIP 还会被上传到该目标的 backups/backup-<timestamp>.zip。
  • 恢复前检查 会显示文件数、页面数、笔记数、卷、模板、预设、将被覆盖的文件数以及归档大小。
  • 恢复 会写入 data/ 下的同名文件，但不会删除备份中不存在的页面。在发生任何覆盖之前，当前数据的快照会先写入 exports/，因此误点也可以撤销。

.mnproj 项目包 ​

一个包含 manifest.json、页面 JSON、模板和预设的 ZIP，有两种模式：

  • 引用（Reference） —— 记录图片路径和 SHA-1 哈希。体积小。如果图片被移动，导入时可以重新关联：先在选定文件夹中按哈希匹配，再按文件名匹配。
  • 打包（Packaged） —— 把去重后的图片嵌入 assets/<sha1>.<ext>。自包含、可移植，但体积大。

导入行为：

  • 首先写入 data/ 的快照。
  • 原始项目包保留在 data/backups/projects/ 下。
  • 冲突可以按覆盖、合并或跳过处理。
  • 合并会在传入页面缺少分格/标注时保留已有的分格/标注，按 id 合并笔记，并且从不会删除已有笔记。

清单字段和文件夹布局请参见数据格式。

推荐实践 ​

  1. 把 raw/ 放在大容量本地磁盘（或外接硬盘）上。它是数据的主体，并且已被 gitignore。
  2. 定期用备份 ZIP 备份 data/。它体积小——主要是 JSON——却包含你所有的工作成果。
  3. 使用 .mnproj 引用模式在已经拥有相同图片的机器之间迁移标注。
  4. 使用 .mnproj 打包模式把一个自包含的项目交给别人。
  5. 保留一份 exports/ 的副本，如果你想留存生成的学习文档；它已被 gitignore，可以重新生成。
  6. 大图库可以放在 NAS 上并使用远程图片源；按需缓存让浏览保持流畅，同时避免在本地保留完整副本。

为什么不直接同步文件夹？ ​

你可以把 raw/、data/ 和 exports/ 放在网络驱动器或同步文件夹中。应用不会锁定文件，但写入是原子性的（.tmp + 重命名），因此同步客户端不太可能看到写了一半的 JSON。避免同时从两台机器编辑同一页；后写入的会覆盖先写入的。

定时备份与仍缺失的部分 ​

定时备份已在「备份 / 还原」对话框里提供：勾选启用、设置间隔（1–168 小时）和自动备份的保留份数（1–50）后保存即可。调度器只在本机 exports/ 写 auto-backup-*.zip，并按保留份数清理旧的自动备份，绝不删除手动的 backup-*.zip；细节见工程文件与格式。失败会以 ERR_AUTO_BACKUP_FAILED 返回。

仍然缺失：

  • 计划中 data/ 的带版本历史的远程同步 —— WebDAV 目标目前只提供图片并接收备份 ZIP，并不会对标注数据库本身做版本管理。
  • 计划中 定时备份的自动上传 —— 定时运行只写本机 exports/。

在此之前，请把备份 ZIP、远程备份上传和 .mnproj 视为受支持的迁移机制。

恢复检查清单 ​

  1. 点击 备份，确认 ZIP 出现在 exports/ 中（或出现在选定的远程目标上）。
  2. 要恢复时：选择 检查，查看各项计数，然后选择 恢复。
  3. 恢复后重新加载图库；带有标注的页面会在侧边栏中显示徽章。
  4. 如果项目导入报告图片缺失，把重新关联目录指向包含这些图片的文件夹，然后用合并再次导入。
