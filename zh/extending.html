布局模板与插件 ​

有两个扩展点，让你不用改应用代码就能替换或约束自动分格检测——杂志版式比普通 XY-cut 更难对付时，就靠这两个口子。

优先级 ​

检测某一页时，服务器按以下顺序尝试：

  1. 绑定到页面、话或卷的布局模板。
  2. plugins/ 或 data/plugins/ 中的匹配插件。
  3. 内置的 XY-cut 检测器。

布局模板始终优先。插件抛出异常、超时（2.5 秒）或没有返回任何分格时，会回退到内置检测器，并在界面上给出警告。

把它想成三位证人：你写的模板先发言，安装的插件随后作证，检测器最后靠猜。

布局模板 ​

布局模板把页面描述为行与单元格组成的网格。它们非常适合整话复用的固定杂志版式。

最小示例 ​

data/layouts/four-panel.json：

json
{
  "id": "four-panel",
  "name": "四格等分",
  "scope": "chapter",
  "volume": "点兔第14卷",
  "chapter": "172",
  "readingDirection": "rtl",
  "margin": { "top": 0.03, "right": 0.03, "bottom": 0.03, "left": 0.03 },
  "gap": 0.012,
  "grid": {
    "cols": 2,
    "rows": [
      { "height": 1, "cells": [{}, {}] },
      { "height": 1, "cells": [{}, {}] }
    ]
  }
}

约定 ​

字段是否必需含义
id推荐文件会保存为 <id>.json；省略时会自动生成。
name推荐在界面和 CLI 中显示。
scope是具体程度为 page > chapter > volume。
volume是必须与卷文件夹名一致。
chapter话/页面级必填必须与话文件夹名一致。
pageIndex页面级必填从 0 开始。
grid.cols是1–12。
grid.rows[].cells是每个单元格可以设置 span（默认 1）。
grid.rows[].height否相对高度权重（默认 1）。
margin否页面比例；每边默认为 0.02。
gap否比例，限制在 0–0.08，默认 0.012。
colWeights否相对列宽；默认等宽。
pageOverrides否键是从 1 开始的页码；可以覆盖 grid、margin、gap、colWeights。
readingDirection否rtl（默认）、ltr、ttb、horizontal-rl、horizontal-lr、vertical-rl、vertical-lr。

服务器会把网格展开为归一化的分格矩形。行和单元格在边距内布局，扣除间距，并遵循跨列与权重。

管理模板 ​

  • 从分格工作台捕获当前页为布局（通过 POST /api/layouts/capture 存储）。
  • 把布局应用到页面、话或卷（POST /api/layouts/apply）。
  • 文件可以手写并纳入版本控制。格式错误的文件会被忽略，而不会破坏图库。
  • CLI：apply-layout --layout <id> --volume <V> [--chapter <C>] [--pages 1,2]。

何时优先用布局而不是分格模板 ​

分格模板布局模板
来源从某一页复制的精确矩形声明式网格
复用相同的页面几何共享同一网格的许多页面
可编辑性通过界面纯 JSON，便于 diff
优先级手动应用检测时自动应用

分格插件 ​

插件是 plugins/ 或 data/plugins/ 中的 JS 模块。.mjs、.cjs 和 .js 都会被加载。文件按目录顺序尝试：先 plugins/，再 data/plugins/，第一个匹配的插件生效。每个目录内按文件名自然排序（page2.js 排在 page10.js 前），所以两个插件争同一页时，文件名决定优先级。加载时抛错的文件会中断查找；没有有效导出的文件会被跳过。

可用的最小插件 ​

plugins/example-2x2-grid.mjs：

js
export default {
  name: 'example-2x2-grid',
  match: { volume: /example/i },
  panels({ width, height }) {
    void width
    void height
    const gap = 0.01
    const w = (1 - gap) / 2
    const h = (1 - gap) / 2
    return [
      { x: 0, y: 0, w, h },
      { x: w + gap, y: 0, w, h },
      { x: 0, y: h + gap, w, h },
      { x: w + gap, y: h + gap, w, h },
    ]
  },
}

规则与失败行为 ​

  • 返回空数组即视为失败：调用方会回退到自动检测。
  • 异常和超时（2500 毫秒）会被捕获；界面会显示警告并使用内置检测器。
  • 矩形会被限制在 0..1，且宽高最小为 0.005。无效条目会被丢弃。
  • match 对字符串是不区分大小写的子串检查，对正则是正则测试。省略 match 会匹配所有内容——开发时有用，但留在生产环境中很危险。
  • 插件会通过 mtime 缓存失效机制重新导入，因此编辑文件后不需要重启服务器。
  • 插件在服务器进程中运行，拥有完整的 Node 访问权限。只安装你信任的插件。

查看插件 ​

bash
node scripts/manga-cli.ts plugins

这会列出每个插件文件、其声明的名称以及任何加载错误。

批处理 CLI ​

CLI 直接操作 raw/ 和 data/，无需启动浏览器。它是一个 TypeScript 入口，依赖 Node 内置的类型剥离（Node 22.6+ 需要加标志，Node 23.6+ 默认启用；Node 26 开箱即用）。

bash
node scripts/manga-cli.ts <command> [options]
命令用途
report [--narrow]扫描每一页，打印分格数量直方图。--narrow 会列出贴边的窄条（あらすじ 误判的候选）。
regress [--update]对照 scripts/detect-baseline.json 比较分格数量；--update 会重写基线。
detect --volume V [--chapter C] [--pages 1,2] [--lang ja] [--plugin NAME] [--auto] [--apply] [--overwrite]用与界面相同的优先级运行检测。不带 --apply 时为试运行。--auto 强制使用内置检测器。
apply-layout --layout ID --volume V [--chapter C] [--pages 1,2]展开并应用一个布局模板。
apply-template --template ID --volume V --chapter C [--pages 1,2]应用已保存的分格模板。
apply-align --preset ID --volume V --chapter C [--pages 1,2]应用一个对齐预设。
templates列出分格模板。
layouts列出布局模板。
align-presets列出对齐预设。
plugins列出已安装的分格插件。

当分格数量不变时，detect 会按阅读顺序重新映射分格级笔记；否则只保留页面级笔记——这与界面在应用模板时使用的规则相同。

示例：

bash
node scripts/manga-cli.ts detect --volume 点兔第14卷 --chapter 172 --pages 1,2 --apply
node scripts/manga-cli.ts report --narrow
node scripts/manga-cli.ts regress

供扩展使用的 HTTP API ​

界面之外的一些有用端点：

方法路径用途
GET/api/layouts列出布局模板。
POST/api/layouts保存一个布局。
POST/api/layouts/capture把当前页捕获为布局。
POST/api/layouts/apply把布局应用到页面。
DELETE/api/layouts?id=…删除一个布局。
GET/api/plugins列出插件和加载错误。
POST/api/detect按模板 → 插件 → 自动的优先级检测分格。
GET/api/panel-templates列出分格模板。
POST/api/panel-templates/apply应用一个分格模板。
GET/api/align-presets列出对齐预设。
POST/api/align-presets/apply应用一个对齐预设。
POST/api/export执行一次 HTML 导出。

完整的端点列表见数据格式和服务器源码（server/app.ts）。
