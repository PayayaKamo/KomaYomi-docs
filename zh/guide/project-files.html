工程文件与格式 ​

KomaYomi 存储的一切都是普通文件：图片在 raw/，标注在 data/，生成结果在 exports/。本页介绍把这份工作搬到别处的三种方式，以及让旧文件保持可读的版本规则。

它解决什么问题 ​

标注是最昂贵的部分——数小时的分格修正、对齐和笔记。它们必须经受换机器、磁盘损坏、与学习伙伴共享，以及未来的应用版本。数据库备份是不透明的；这些格式是普通的 ZIP 和 JSON，用常规工具就能检查。

三个可移植层 ​

层文件内容何时使用
工程包.mnproj图片（打包模式）、页面 JSON、模板、预设、语言映射换到另一台机器，或归档已完成的卷。
交换文件.mntpl、.mnexp、.mnpage.json一个版式、一种导出样式，或一页分享可复用的版式或单个已标注页面。
备份 ZIP.zip整个 data/ 文件夹误操作后恢复，或保留定期安全副本。

工程包（.mnproj） ​

.mnproj 是一个带文本清单的 ZIP：

text
manifest.json
pages/<volume>/<chapter>/<index>.json
history/<volume>/<chapter>/<index>.json
templates/...
presets/...
config/library.json          (optional)
assets/<sha1>.<ext>          (packaged mode only)

页面版本历史会随工程一起迁移，重新打开后仍能看到切格工作台里描述的记录。

引用模式与打包模式 ​

模式图片体积可移植性
引用清单中只记录路径与 SHA-1 哈希。小。需要原始图片文件夹。支持按哈希或文件名补链。
打包去重后存入 assets/<sha1>.<ext>。大。自包含；导入时把图片写入 raw/。

导出 ​

  1. 打开侧栏的 工程文件…，或 文件 → 另存为工程…。
  2. 选择模式，填写工程名称和可选备注。
  3. 点击 生成并下载 .mnproj。

清单记录应用版本、创建时间、语言映射、卷 / 话 / 页清单与图片哈希，以及笔记和标注数量。

导入 ​

  1. 选择工程文件…。写入任何内容之前，对话框会先汇总卷、话、页、笔记、标注、图片和模板。
  2. 选择冲突策略：覆盖、合并 或 跳过。
    • 合并 在传入页面缺少分格和标注时保留现有内容，并按 id 合并笔记，不删除已有笔记。
  3. 引用模式工程缺少图片时，可选一个存放原图的 补链目录。
  4. 点击 导入。

安全行为：

  • 导入前会把当前 data/ 快照到 exports/。
  • 原工程文件备份到 data/backups/projects/。
  • 导入后会报告缺失的图片；把它们放进补链目录，再用 合并 导入一次即可找回。

交换文件 ​

交换文件… 负责三种小格式，不触碰整个图库。

.mntpl —— 版式模板 ​

导出时会剥离卷 / 话 / 页绑定，因此模板可以导入另一部漫画，再重新绑定到当前卷、话或页。导入对话框可以绑定，并可选立即套用；已有页面会先保存。

.mnexp —— 导出模板 ​

保存 HTML 和 PNG 导出的版式与样式设置。可以现在导出、以后导入。模板存储在 data/templates/export.json。

.mnpage.json —— 单页 ​

可读的页面文档，包含分格、笔记、标签、分组、标注和对齐偏移。没有 schema 外壳的旧页面 JSON 也能导入，并会自动迁移。

  • 导出当前页 写出当前页。
  • 选择页面 JSON… 然后 覆盖当前页 会替换所选页的分格、笔记和标注。
  • 校验失败会报告确切的字段路径，绝不写入半成品数据。
  • 原文件备份到 data/backups/exchange/。

未保存的改动

如果页面有未保存的编辑，交换导出不会包含它们，页面导入也可能覆盖它们。请先保存——对话框会警告，但很容易点过去。

格式版本 ​

每种交换格式都带一个 schema 外壳：

json
{
  "$schema": "https://manga-memo.dev/schemas/page.schema.json",
  "schemaVersion": 1,
  "appVersion": "0.1.0",
  "kind": "page"
}
类型文件当前版本
mnproj.mnproj 清单1
mntpl版式模板1
mnexp导出模板1
page页面文档1
mntp分格模板（存储）1
mnalign对齐预设（存储）1
mnlayout声明式布局（存储）1
mnconfig图库配置（存储）1
mnstorage存储配置（存储）1

版本规则：

  • 声明版本高于应用支持的文件会被拒绝，并给出明确提示：先升级应用。应用绝不猜测未来的格式。
  • 缺失版本按 v0 处理，并在导入时迁移。早期的实验性清单（顶层 images、扁平的 langDirs 映射）会转换为当前结构。
  • 缺失的可选字段用默认值填充；无效图片会被丢弃，而不是让整个导入失败。
  • 读取页面 JSON 时会规范化：限制矩形范围、移除悬空的分组引用、生成缺失的 id、丢弃未知字段。
  • 无法解析的页面 JSON 视为不存在；应用会重新检测并重建。

备份 ZIP ​

备份是一个 ZIP，条目以 data/ 为前缀：

text
data/pages/...
data/templates/...
data/presets/...
data/layouts/...
data/library.json
data/.backup-meta.json

排除：data/cache/（缩略图与远端缓存）、.tmp 文件和日志。恢复会覆盖同名文件，保留备份中没有的页面，并先写入快照。

尚未实现 ​

  • PDF 和 Word（.docx）导出，以及词表导出。请使用 HTML 导出和浏览器的打印为 PDF。
  • 定时备份。 备份和上传到备份目标都需要手动启动。
  • 应用内的图片转换或批量重命名。 请在导入前整理文件；见预处理与重命名。

常见坑 ​

  • 引用模式的工程显示缺图。 清单只存哈希和路径。使用补链目录，或下次用打包模式导出。
  • “Schema 版本过新。” 文件来自更新的版本。请更新应用；不要手工修改 schemaVersion。
  • 导入覆盖了更新的笔记。 覆盖 按设计就是破坏性的。拿不准时用 合并；虽然写入了快照，但恢复快照会替换当前数据。
  • 版式模板没有出现。 它绑定在当前的话 / 卷筛选上；检查导入对话框中的绑定。
  • .mnpage.json 导入后没有图片。 页面数据从不包含图片；图片来自 raw/ 或打包工程。
