预处理与重命名 ​

KomaYomi 直接在你现有的图片文件夹里读取，不会复制、转换或重命名任何文件。也就是说，把一卷漫画加进图库前花的那几分钟整理，直接决定切格、配对和对照阅读顺不顺。有点烦，但总比同一页在三种语言里各修一遍便宜。

这一步解决什么问题 ​

自动切格偏爱干净的书页扫描。页面转倒了、扫描仪黑边还在、混着一堆 WebP、某个版本少了一页——图库照样能打开，但后面的每一步（配对、对齐、笔记、导出）都会继承这些毛病。在源头修一次就好。

KomaYomi 会怎样处理你的文件 ​

行为后果
图片从你指定的文件夹就地读取。不会导入或复制，所有编辑都只写进 data/。
页面按排序位置配对，而不是按文件名。改名会改变顺序。中间插入一页，后面的每一页都会顺延。
排序是自然排序：连续数字按数值比较。即使不补零，2.jpg 也会排在 10.jpg 前面。
WebP 能显示，但不会解码用于切格检测。依赖自动切格时，请把 WebP 转成 JPEG 或 PNG。
一个图片文件就是一页。跨页扫描必须保持为一个文件，除非你在每种语言里都做了同样的拆分。

整理清单 ​

如果原图很珍贵，先复制一份再动手。下面的顺序比用什么工具更重要。

  1. 转正、校正倾斜。 阅读方向是按页保存的，但一张横躺的扫描图，对照阅读救不回来。
  2. 裁掉扫描仪黑边和对页阴影。 页边方正时，贴着边缘的分格更容易被正确检测。
  3. 需要自动切格就把 WebP 转成 JPEG 或 PNG。 画质要足够高，保证台词仍然清楚。
  4. 一话一个文件夹。 不要把两话混在同一目录里；话是分格模板、对齐预设和导出的基本单位。
  5. 去掉不是正文页的图，例如封面、版权页、彩插，或另一版根本没有的赠品图。多出一页，后面每一页都会跟着错位。
  6. 跨页要么不拆，要么每版都拆。 一张跨页算一页。如果只拆了日文生肉、没拆中文熟肉，日文的第 12 页就会对应中文的第 12–13 页，配对立刻乱掉。
  7. 只在确实有帮助时规范文件名。 补零（001.jpg）便于对比和人工检查，但扫描器用的是排序位置和自然排序，1.jpg 与 001.jpg 都能用。

批量重命名一话 ​

目前应用内还没有批量重命名或图片转换功能——计划中。预处理… 对话框可以改卷或话的显示标题，也能调整页序、排除页面，但它只写图库配置（library.json），磁盘上的文件名保持原样。真要改名，请用文件管理器或命令行。Windows 上可以先用 PowerShell 排序后重新编号：

powershell
# 先预览：-WhatIf 只打印计划中的改名，不会真的改动。
Get-ChildItem -File | Sort-Object Name | ForEach-Object -Begin { $i = 1 } -Process {
  $new = '{0:D3}{1}' -f $i, $_.Extension.ToLower()
  Rename-Item -LiteralPath $_.FullName -NewName $new -WhatIf
  $i++
}

确认预览无误后再去掉 -WhatIf，并对这一话的每种语言文件夹各执行一次。只有在页数和顺序都不变时，改名才不影响已有标注：页面数据是按话和页序号索引的，不是按文件名。

改名可能让标注对不上页

如果改名改变了页数或页序，data/pages/<卷>/<话>/<序号>.json 就不再指向你编辑过的那一页。请在开始修分格之前完成改名，或者改完之后从备份恢复。

开始标注前的确认 ​

  1. 加入这一卷，在侧栏里打开。
  2. 看卷和话那一行的警告。各语言页数不一致 和 文件名与页序不符 这两条，通常说明整理时出了问题。
  3. 如果目录形状特殊，先打开目录识别规则…，用预览确认后再保存；见目录识别规则。
  4. 打开第一页、中间一页和最后一页，确认同一个分格里确实是同一块画面；如果不是，说明页数或跨页处理有问题。
  5. 这时再运行自动切格，开始写笔记。

常见坑 ​

  • 某种语言多了一页。 多半是多了一张封面或版权页。删掉它，或者给其他语言补上对应的一页。
  • 跨页只在一个版本里拆开了。 要么整页保留，要么每个版本都在同一位置拆。
  • WebP 页面自动切格结果很乱。 转成其他格式；检测不会解码 WebP。
  • 改名后笔记跑到了下一页。 页面数据按序号索引。请在标注前改名，或者用页面历史确认发生了什么。
  • 页面看起来没问题，缩略图却格式不一。 缩略图跟随文件内容而不是扩展名，一个其实是 JPEG 的 .png 仍能正常显示，这只是外观问题。
  • 标注之后才重组了文件夹。 识别出的 ID 变了，旧的页面数据就找不到了。目录规则要在标注之前应用。
