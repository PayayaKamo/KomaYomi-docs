数据格式 ​

KomaYomi 存储的一切都是纯 JSON 或纯图片文件。本页记录磁盘上的约定，便于你写脚本、做 diff 或手工修复。

文件映射 ​

路径内容
raw/<volume>/<language>/<chapter>/*.jpg页面图片（输入，永远不会被修改）。
data/pages/<volume>/<chapter>/<index>.json每页一个页面文档（index 从 0 开始）。
data/templates/panels/<id>.json已保存的分格模板。
data/templates/export.json已保存的导出模板（一个数组，每项自带信封）。
data/presets/align/<id>.json已保存的对齐预设。
data/layouts/<id>.json声明式布局模板。
data/library.json手动指定的语言目录映射。
data/cache/thumbs/缩略图缓存（可以安全删除）。
data/backups/导入的 .mnproj 文件的副本。
exports/生成的 HTML、PNG、备份 ZIP 和项目文件。

写入是原子性的：服务器先写入 <file>.tmp，再重命名覆盖目标文件。即使崩溃，旧文件也会保持完整。

信封 ​

除项目清单外，每个持久化或交换的 JSON 文件都以同样的四个键开头：

json
{
  "$schema": "https://manga-memo.dev/schemas/page.schema.json",
  "schemaVersion": 1,
  "kind": "page",
  "appVersion": "0.1.0"
}
1
2
3
4
5
6
键含义
$schema该格式的规范地址。仅作说明，应用不会去请求它。
schemaVersion整数版本。没有这个键的文件按 v0 读取。
kind类型标记：page、mnproj、mntpl、mnexp、mntp、mnalign、mnlayout、mnconfig、mnstorage、mnhistory。
appVersion生成该文件的构建版本。只用于诊断，从不参与选择迁移。

.mnproj 里的 manifest.json 是唯一例外：它带 $schema、schemaVersion 和 appVersion，但不带 kind，因为压缩包本身就说明了格式。

字段参考 ​

字段类型说明
$schema、schemaVersion、kind、appVersion见上信封；kind 为 page。
volume、chapterstring必须与文件夹名一致。
pageIndexnumber从 0 开始。
panelsPanel[]见下文。坐标会被限制在 0..1；宽高至少为 0.005。
notesNote[]scope 为 page 或 panel；分格笔记必须带 panelId。没有字符串 text 的记录会被丢弃。
offsetsRecord<Lang, AlignOffset>页面级对齐。scale 被限制在 0.2..4。
alignModepage | panel | anchors | grid无效值会变成 page。
panelOffsetsRecord<panelId, Record<Lang, AlignOffset>>分格级对齐。
gridStepnumber百分比，限制在 0.1..10，默认 1。
readingDirectionrtl | ltr | ttb | horizontal-rl | horizontal-lr | vertical-rl | vertical-lr无效值会变成 rtl；旧文件中已移除的 continuous-vertical 也按 rtl 读取。
detectorVersionstring例如 xycut-1.3、layout:<id>、plugin:<name>。
detectedAtISO string最后一次检测的时间。
detectSourceauto | template | plugin | manual分格是由哪条路径产生的。
editCountnumber每次写入都会递增。不是审计日志。
lastEditedAt、lastEditSummarystring人类可读的变更摘要。
groupsPanelGroup[]读取时会移除悬空的分格 id；空分组会被丢弃。
annotationsAnnotation[]无效的点会被丢弃。
annotationsVisibleboolean为 false 时在界面和导出中隐藏标注图层；数据仍然保留。
updatedAtISO string写入时由服务器设置。

  • id 在页面内局部有效，且必须唯一。
  • x、y、w、h 以页面为基准归一化。

笔记（Note） ​

字段类型说明
idstring在页面内唯一。
scopepage | panel
panelIdstring | null分格范围时必填。
textstringMarkdown。原始 HTML 会被转义。
tagsstring[]
source{ title?, url?, text? }text 是自由形式的来源标签。
images{ id, name, dataUrl }[]笔记附带的截图。可在笔记编辑器中粘贴、拖入或添加；超过 400 KB 的图片会缩小到长边 1600 px。
createdAt、updatedAtISO string

标注类型 ​

arrow、rect、ellipse、highlight、text、badge、mosaic、pen。

坐标相对于标注的作用范围（页面框或分格框）。自由画笔使用完整的 points 折线；箭头使用首尾两个点。

可选的 anchor 是页面坐标里的定位点：{ "x": 0.5, "y": 0.4 }，带 w / h 时表示一个框。标注会指向它；showLeader 控制是否画从标注到定位点的引出线，缺省视为 true（JSON 里通常直接省略）。

版本规则 ​

页面文档 ​

  • schemaVersion 目前为 1。没有这个键的文件按 v0 处理，读取时迁移：补上信封并删除旧的 version 键。
  • 更高的 schema 版本在写入时会被拒绝，报 ERR_SCHEMA_TOO_NEW，避免旧版本悄悄降级新文件。
  • 读取时会规范化取值：无效数字变为默认值，矩形被限制范围，悬空的分组引用被移除，缺失的 id 会被生成。
  • 顶层未知字段会经 preserveUnknown 在读取 → 写入之间保留。带 id 的对象数组按 id 合并，其他数组用新值覆盖。
  • panels、notes、groups、annotations 这些已知子对象在写入时逐字段重建，因此它们内部的未知字段不保证保留。
  • 无法解析的页面 JSON 会被视为不存在；应用随后会自动检测并重新创建它。
  • 迁移按版本串联（0 → 1 → …）；每一步只新增或重命名字段，不会删除用户内容。

项目包 ​

  • schemaVersion 目前为 1。
  • 声明了更高版本的项目包会被拒绝，并给出明确错误：请先升级应用。
  • 版本 0 的项目包（早期实验）会在导入时迁移：顶层的 images、file 字段和扁平的 langDirs 映射会被转换为当前的 manifest 结构。
  • 缺失的可选字段会用默认值填充；无效的图片会被丢弃，而不是中止导入。

存储模式 ​

模式图片大小可移植性
reference清单中只有路径 + SHA-1。小。需要原始图片。支持按 SHA-1 或文件名重新关联文件夹。
packaged去重后放入 assets/<sha1>.<ext>。大。自包含；导入时会把图片写入 raw/。

导入会逐文件检查冲突，并提供覆盖、合并或跳过：

  • 合并会在传入页面缺少分格/标注时保留已有的分格/标注，按 id 合并笔记（同一 id 以传入的为准），并且从不会删除已有笔记。
  • 每次导入前都会先给 data/ 拍一份快照；原始项目包也会保留在 data/backups/projects/ 下。
