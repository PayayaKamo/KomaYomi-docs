Server & CLI message codes ​

KomaYomi keeps every user-facing sentence produced by server/ and scripts/ in one trilingual catalog (server/messages/catalog.ts). Domain code raises a stable code plus parameters; the text is rendered at the boundary in the language negotiated for that request (HTTP) or invocation (CLI).

ERR_* / WARN_* / STATUS_* codes are public API — clients and scripts may match on them, so renaming a code is a breaking change. Adding a code is not.

  • Catalog: server/messages/catalog.ts
  • Language negotiation: server/messages/index.ts
  • Error type: server/errors.ts

HTTP response contract ​

Every error response keeps the legacy error string (the current client reads it) and adds the structured fields:

json
{
  "error": "Page not found: 点兔第14卷 / 172 page 99",
  "message": "Page not found: 点兔第14卷 / 172 page 99",
  "code": "ERR_PAGE_NOT_FOUND",
  "params": { "volume": "点兔第14卷", "chapter": "172", "page": 99 },
  "lang": "en"
}

FieldMeaning
errorLocalized text (kept for backwards compatibility).
messageSame text as error, for clients written against the new contract.
codeStable machine-readable code from this document.
paramsValues interpolated into the text; never localized.
langLanguage actually used for error / message.

sendJson also sets Content-Language: <lang> and Vary: Accept-Language.

Warnings embedded in successful payloads stay string[] (localized for the request), so existing UI code keeps working. POST /api/detect additionally returns warningCodes: [{ "code": "WARN_…", "params": { … } }] for the warnings it generates itself.

Language negotiation ​

Priority, highest first:

  1. ?lang=zh query parameter (en / zh / ja, region tags such as zh-CN accepted).
  2. Accept-Language header, q-values respected (ja;q=0.9, en;q=0.4).
  3. Environment: KOMAYOMI_LANG, then MANGA_LOCALE, then LC_ALL / LANG.
  4. English.
bash
curl -s 'http://127.0.0.1:5173/api/page?volume=V&chapter=1&index=999' \
  -H 'Accept-Language: ja-JP,ja;q=0.9'
# → {"error":"ページが見つかりません：V / 1 …","code":"ERR_PAGE_NOT_FOUND",…}

CLI ​

scripts/manga-cli.ts renders the same catalog.

bash
node scripts/manga-cli.ts report --lang ja
KOMAYOMI_LANG=zh node scripts/manga-cli.ts layouts
LANG=ja_JP.UTF-8 node scripts/manga-cli.ts report
1
2
3
  • --lang en|zh|ja wins, region tags are normalized (zh-CN, ja_JP).
  • Without the flag the CLI follows KOMAYOMI_LANG → MANGA_LOCALE → LC_ALL/LANG, then English.
  • --content-lang ja selects which image files to read (formerly the overloaded --lang); --image-lang is accepted as an alias.
  • Errors print as Error: <localized message> on stderr and exit with status 1.

Other message codes ​

These are also localized but are data rather than diagnostics:

  • STATUS_STORAGE_* — storage probe results (online, message) in GET /api/storage and POST /api/storage/test:

    CodeMeaning
    STATUS_STORAGE_LOCAL_OKLocal directory is reachable
    STATUS_STORAGE_NETWORK_OKNetwork share is reachable
    STATUS_STORAGE_WEBDAV_OKWebDAV is reachable
    STATUS_STORAGE_DIR_NOT_CREATEDTarget directory does not exist yet
    STATUS_STORAGE_ACCESS_FAILEDCannot access it (detail attached)
    STATUS_STORAGE_TIMEOUTConnection timed out
    STATUS_STORAGE_UNREACHABLECannot connect

  • HISTORY_* — lastEditSummary values stored in page docs (written in the language of the request that saved the page): HISTORY_CREATED, HISTORY_PANELS, HISTORY_PANEL_RECTS, HISTORY_NOTES, HISTORY_NOTE_EDIT, HISTORY_DIRECTION, HISTORY_GROUPS, HISTORY_ANNOTATIONS, HISTORY_ALIGN_MODE, HISTORY_OFFSETS, HISTORY_SAVE, HISTORY_DETECTED.

  • EXPORT_* — labels inside exported HTML: EXPORT_DIRECTION_RTL, EXPORT_DIRECTION_LTR, EXPORT_DIRECTION_TTB, EXPORT_PAGE_NOTES, EXPORT_PANEL_NO, EXPORT_EMPTY_PANELS, EXPORT_EMPTY_IMAGE, EXPORT_EMPTY_NOTES, EXPORT_PAGE_ALT, EXPORT_CHAPTER_LINE, EXPORT_AT, EXPORT_FOOTER.

  • LANG_NAME_JA, LANG_NAME_ZH, LANG_NAME_EN, LABEL_*, DEFAULT_NAME_* — display names and default titles.

  • CLI_* — CLI-only lines: CLI_USAGE, CLI_ERROR, CLI_REPORT_SUMMARY, CLI_REPORT_HISTOGRAM, CLI_REPORT_HISTOGRAM_ITEM, CLI_REPORT_NARROW, CLI_REGRESS_BASELINE, CLI_REGRESS_RESULT, CLI_DETECT_SKIPPED, CLI_DETECT_SKIPPED_EXISTING, CLI_DETECT_PAGE, CLI_DETECT_WRITTEN, CLI_DETECT_PREVIEW, CLI_DETECT_WARNING_SUFFIX, CLI_DETECT_DONE, CLI_LAYOUT_APPLIED, CLI_LAYOUT_NONE, CLI_LAYOUT_ROW, CLI_PLUGIN_NONE, CLI_PLUGIN_ROW, CLI_PLUGIN_ROW_ERROR, CLI_PLUGIN_FAILED, CLI_TEMPLATE_APPLIED, CLI_TEMPLATE_NONE, CLI_TEMPLATE_ROW, CLI_ALIGN_APPLIED, CLI_ALIGN_NONE, CLI_ALIGN_ROW, CLI_NO_RESULT.

  • CLI-only errors: CLI_TEMPLATE_ARGS_REQUIRED (missing --template/--volume/--chapter), CLI_TARGET_CHAPTER_MISSING, CLI_MISSING_STATIC_DIR.

Adding or changing a message ​

  1. Add the code to MESSAGES in server/messages/catalog.ts with all three languages (en is the fallback and must always be present).
  2. Use t('CODE', { param }) for user-facing text, or throw new AppError('CODE', { param }, status) for failures. Never concatenate translated fragments — pass values as parameters.
  3. Add a row to the matching table above (and to the warning table for WARN_*).
  4. Run npm run typecheck, npm run lint and npm run format:check — the catalog key type is derived from MESSAGES, so a typo becomes a compile error.
