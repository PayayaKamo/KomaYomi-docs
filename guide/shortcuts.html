Keyboard Shortcuts ​

One page for every key and mouse gesture. Single-key shortcuts are ignored while focus sits inside a text field, so typing a note never flips the view mid-sentence.

What this page solves ​

Shortcuts are scattered across the library, the workbench, the compare reader and the notes editor. Rather than hunting through each chapter, keep this page open while you learn the workflow, or print it and tape it next to the monitor.

In read mode the editing shortcuts (Ctrl+Z, Ctrl+Y, save, panel and annotation keys) do nothing; page turning and the view switches still work.

Focus mode ​

Press R or click ⛶ in the top bar to enter: the top bar, stage toolbar, panel section rail and status bar fold away so the page fills the window. It does not change the edit/read mode. Leave with Esc (when no dialog is open), R again, or by double-clicking empty space on touch devices. The state is remembered across sessions. A short tip names the exit gesture on entry, then fades out and never covers the artwork.

These file shortcuts work even while typing, matching desktop apps.

Mouse-only actions ​

Some controls have no keyboard equivalent by design:

  • Pane splitters: drag to resize, double-click to reset.
  • Language chip reordering in the compare reader: drag a chip.
  • Zoom buttons: − / ＋ in the panel toolbar.
  • Panel template and alignment preset pickers.

Common pitfalls ​

  • A shortcut types a letter instead. Focus is in an input, textarea or contenteditable element. Click the stage first.
  • H does not mask. The focus is in a note or toolbar field; the compare shortcut is ignored while typing.
  • E does nothing. No page is open, so the export dialog is unavailable.
  • Ctrl+Z undoes a note instead. Inside a text field the browser's native undo applies; page-level undo only works on the stage.
