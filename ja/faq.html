FAQ とトラブルシューティング ​

ライブラリが空です ​

症状: サイドバーに「巻が見つかりません」と表示されます。

raw/ 以下のフォルダ構成を確認してください:

text
raw/<volume>/<language-dir>/<chapter>/001.jpg

よくある原因:

  • 巻フォルダはありますが、言語フォルダが認識されていません。巻の設定で対応付けるか、ja、zh、en に名前を変更してください（別名は ライブラリ に一覧があります）。
  • 話フォルダが巻の直下にあります（raw/<volume>/001.jpg）。言語ディレクトリが必要です。
  • デスクトップアプリのデータディレクトリが別の場所を指しています。Ctrl+Shift+D を押して正しいフォルダを選ぶか、MANGA_DATA_DIR を設定してください。

あるページで言語が欠けています ​

症状: ページに JA と ZH しか表示されず、EN が無効になっています。

ページは並べ替えたインデックスで対応付けられます。その話で英語のファイルが1つ少ない場合、最後のページには英語の画像がありません。ページの警告に、欠けている言語とページ番号が示されます。ファイルを追加するか、余分なページを削除してください。

件数は一致しているのに対応付けが誤っている場合は、ファイル名を確認してください。先頭の番号が並べ替えた位置と一致しない場合に警告が出ます。自然順が意図した順序になるようにファイル名を変更してください。

ファイル名は問題ないのにページの順序がおかしい ​

並べ替えは自然順です。数字の連続は数値として比較されるため、2.jpg は 10.jpg より前に来ます。バイト単位の辞書順ではありません。先頭に番号のないファイルは、番号付きのファイルより前に並ぶことがあります。ページには 001.jpg、002.jpg のように一貫した接頭辞を付けてください。

コマ検出が正確ではありません ​

  • 左右の縦帯は無視されます。 これは意図的です。端の細い帯（通常は あらすじ や作者コメント）は、誤ったコマにならないようフィルターされます。正規の端のコマは手動で描いてください。
  • 見開きページ はしばしば1つの大きなコマと断片を生成します。断片を選択して 結合 してください。
  • 非常に小さい、または非常に細い枠 はノイズとしてフィルターされます。実際に存在する場合は手動で追加してください。
  • WebP ページは検出のためにデコードされません。自動検出が必要なら JPEG/PNG に変換してください。
  • 固定の雑誌レイアウト には、検出よりもレイアウトテンプレートの方が適しています。

コマを修正した後は、手動の枠を失うことを受け入れない限り、自動検出を再実行しないでください。

エクスポートした HTML に画像が表示されません ​

フォルダモード（既定）: HTML は隣接する <name>.files/ ディレクトリを参照します。.html ファイルと .files フォルダを両方、相対位置を保ったままコピーしてください。HTML だけを開いたり、フォルダから離れた場所に移動したりすると、画像が壊れます。

単一ファイルモード: 画像は埋め込まれているため、HTML ファイルだけが必要です。代償はサイズで、話全体では数十メガバイトになることがあります。

元の画像が見つかりません ​

症状: .mnproj のインポートで画像が見つからないと報告される、またはページに 404 のプレースホルダーが表示されます。

  • 参照モードのプロジェクト はパスを保存し、画像は保存しません。画像が移動した場合は、再度インポートして再リンクディレクトリを設定してください。インポーターはまず SHA-1 で、次にファイル名で照合し、巻名と話名を含むフォルダを優先します。
  • パッケージモードのプロジェクト は画像を assets/ に含みます。アセットが見つからない場合はパッケージが不完全なので、再エクスポートしてください。
  • 画像は存在するが名前が変わっている場合は、期待される構造のフォルダに置いて再リンクを使ってください。

編集内容が消えました ​

ツールバーの保存モードを確認してください:

  • 自動 はデバウンスして保存します。
  • 確認 は保存チェックのクリックが必要です。未保存の変更を残して離れるとブラウザの警告が出ますが、クラッシュや強制終了では最後の編集が失われることがあります。

また、同じページを見ているか確認してください。URL ハッシュには巻、話、ページ、ビューが含まれます。別のデータディレクトリでアプリを開くと、別のライブラリが表示されます。

テンプレートを適用したらコマのノートが消えました ​

コマテンプレート（または再検出）でコマ数が変わると、コマスコープのノートは確実にマッピングできないため破棄されます。ページスコープのノートは常に保持されます。コマ数が変わらなければ、ノートは読み順で再マッピングされます。

これを避けるには、話全体にテンプレートを適用する前にバックアップをエクスポートしてください。

ポート 5173 が既に使用されています ​

Vite は strictPort: false で設定されているため、次の空きポートに移動します。実際の URL はターミナルの出力を読んでください。ドキュメントサイトは 5174 を使います。

すべてをバックアップするには ​

  • バックアップ ZIP — data/ のすべて（JSON、テンプレート、プリセット）。サムネイルキャッシュを除きます。
  • .mnproj — プロジェクトパッケージ。画像あり／なし。
  • フォルダのコピー — raw/ は画像、data/ は作業内容、exports/ は再生成可能です。

リモート保存とバックアップ を参照してください。

エラーコードが出たときは ​

サーバーと CLI は ERR_* / WARN_* / STATUS_* の安定したコードを返し、error / message の文言はリクエストの言語にローカライズされます。完全な一覧と HTTP 契約はサーバーと CLI のメッセージコード（英語ページ、英語が正）を参照してください。

サムネイルが古い、または壊れて見えます ​

data/cache/thumbs/ を削除してください。キャッシュであり、オンデマンドで再構築されます。バックアップとプロジェクトパッケージは既にこれを除外しています。

ノートを検索しても何も返りません ​

  • 検索はノート本文、タグ、出典を対象とします。有効な巻／話／タグ／出典のフィルターを確認してください。
  • ノートはインデックスされるために保存されている必要があります。確認モードでは、未保存の編集はまだディスクにありません。
  • 概要はページ JSON をインデックスします。保存に失敗したページには検索可能なノートがありません。

デスクトップアプリは起動するが古いページ群が表示されます ​

デスクトップウィンドウがリポジトリとは別のデータディレクトリを使っている可能性があります。ウィンドウタイトル（データパスを含みます）を確認し、Ctrl+Shift+D を押して切り替えてください。MANGA_DATA_DIR は保存された設定を上書きします。

PDF や Word をエクスポートできないのはなぜですか ​

実装されているのは HTML と PNG だけです。PDF、.docx、語彙リストは 予定 です。回避策として、エクスポートした HTML をブラウザで開き、印刷 → PDF として保存 を使ってください。HTML には、ページを区切り、コマやノートの分割を避ける印刷用のスタイルがあります。

コマのグループを作成できないのはなぜですか ​

ページ JSON は group オブジェクトに対応しており、インポートとエクスポートで保持されますが、グループ編集 UI はまだありません（予定）。JSON を手で編集でき、読み込み時に正規化と検証が行われます。ベクター注釈は実装済みで、コマ分割ワークベンチに矢印、矩形、楕円、ハイライト、フリーハンド、テキスト、バッジ、モザイクのツールがあります。

データはどこかに送信されますか ​

既定ではいいえ。サーバーは 127.0.0.1 で待ち受け、リモート先を設定しない限り何もアップロードされません。外向きリクエストは 2 種類あります。ノートの出典のための任意の「ページタイトルを取得」（入力した URL を5秒のタイムアウトで要求）と、自分で追加した WebDAV／ネットワークストレージ先（画像のオンデマンド取得とバックアップのアップロード）です。ストレージ先を設定しなければ、すべてのデータはローカルに留まります。

古いページ JSON が開きません ​

手で編集した、または古い JSON は読み込み時に正規化されます。欠けた id は生成され、矩形はクランプされ、無効な enum 値は既定値にフォールバックし、ぶら下がったグループ参照は削除されます。ファイルがまったく有効な JSON でない場合、アプリはそのページにデータがないものとして扱い、再検出します。その結果、保存時にファイルが上書きされます。その場合はバックアップから復元してください。

それ以外の問題があります ​

助けを求める前に、次を集めてください:

  1. npm run dev または npm run desktop を起動したターミナルの出力。
  2. 正確なページのパス（data/pages/<volume>/<chapter>/<index>.json）。
  3. data/cache/thumbs/ を削除した後に問題が再現するかどうか。
  4. 検出に関する問題なら node scripts/manga-cli.ts report の出力。
