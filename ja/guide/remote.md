# リモート保存とバックアップ

画像は別のディスク、NAS 共有、WebDAV サーバーに置いたまま、注釈はローカルの `data/` フォルダに保存できます。このページでは、リモートライブラリの動作、オフライン時の挙動、バックアップの仕組みを説明します。

## 解決する課題

漫画ライブラリは、アプリにインデックスさせたいディスクよりはるかに大きいことが多く、すでに NAS にあることもあります。数万枚の画像を `raw/` にコピーするのは無駄です。一方、注釈は小さく、ネットワークが落ちても決して失われてはいけません。

KomaYomi はこの2つを分けます。**画像は必要に応じてリモートから読み、注釈はローカルに書きます。**

## リモートライブラリの設定

1. サイドバーの **バックアップ / 復元** を開きます。
2. **リモート素材 / ネットワークストレージ** で **リモートフォルダを追加** をクリックします。
3. 対象を入力します。

| フィールド | 意味 |
| --- | --- |
| **名前** | ダイアログに表示されるラベル。 |
| **種類** | ローカルフォルダ、ネットワークドライブ / UNC、WebDAV。 |
| **フォルダパス** | 例：`D:\manga` または `\\nas\share\manga`（ローカル / ネットワーク）。 |
| **WebDAV アドレス**、**ユーザー名**、**パスワード** | WebDAV の認証情報。 |
| **読み取り専用** | アプリが書き込まないよう、ソースを読み取り専用にします。 |

4. **接続をテスト** をクリックします。ダイアログに *オンライン* / *オフライン* と、対象が読み取り専用かどうかが表示されます。
5. **リモートのフォルダツリーを同期** をクリックします。

### 同期の動作

アプリはリモートフォルダを走査し、ローカルのミラー（`data/cache/remote/tree/`）に **0 バイトのプレースホルダーファイル** を作成します。通常のライブラリスキャナーとフォルダ規則がそのミラーに対して実行されるため、リモートの巻はローカルと同じように、同じ 巻 → 言語 → 話 のグループ化でサイドバーに表示されます。

- ミラーされるのは画像の拡張子だけです：`.jpg`、`.jpeg`、`.png`、`.webp`、`.gif`、`.avif`、`.bmp`。
- 走査は深さ10階層、**20,000 ファイル** までです。上限に達すると「ファイル上限に達しました」と報告して停止します。
- 読み取れないフォルダはカウントして報告され、同期は中断されません。
- 再度同期するとミラーは置き換わります。注釈は影響を受けません。

## オンデマンドの読み込みとキャッシュ

ページを開くと、次の順に処理されます。

1. アプリはローカルキャッシュに元ファイルがあるか確認します。
2. ない場合、リモートソースからファイルを取得します。
3. バイト列はプロバイダーとパスごとに内容で識別され、`data/cache/remote/files/` に書き込まれます。
4. サムネイルはキャッシュされた元ファイルから生成されます。

「ライブラリ全体をダウンロードする」手順はありません。実際に開いたページだけが取得されます。

| コントロール | 意味 |
| --- | --- |
| **キャッシュ n MB / 上限 MB（m ファイル）** | 現在のキャッシュ使用量。 |
| **キャッシュ上限（MB）** | 上限。既定は **512 MB** で、100,000 までの正の値を指定できます。 |
| **画像キャッシュを消去** | キャッシュされたリモートの元ファイルとサムネイルを削除します。安全に使え、再取得されます。 |

キャッシュが上限を超えると、最も長く使われていないファイルから削除され、使用量が上限の **90%** を下回るまで続きます。

## オフライン時の動作

ネットワークは失われる前提です。

| 状況 | 結果 |
| --- | --- |
| キャッシュ済みのページ | オフラインでも通常どおり開きます。 |
| 未キャッシュのページ、リモートがオフライン | 画像リクエストは HTTP **503** `ERR_REMOTE_UNAVAILABLE` で失敗し、UI は待ち続けずにエラーを表示します。 |
| 未キャッシュのページのサムネイル、リモートがオフライン | HTTP **502** `ERR_THUMB_FETCH_FAILED`。 |
| 注釈、ノート、コマ | 常にローカルです。画像がキャッシュ済みのページは編集を続けられます。 |

オフラインの**書き込み**キューはありません。書き込みはローカルの `data/` フォルダ（常にアプリを動かしているマシン上）へ行われます。

::: tip 実用的なオフライン利用
オフラインになる前に、学習する予定のページを開いておいてください。元ファイルとサムネイルがキャッシュされるため、そのまま読めます。持ち運べる量はキャッシュ上限で決まります。
:::

## パスワードと認証情報

- パスワードは `storage.json` に**保存されません**。
- **AES-256-GCM** で `data/secrets.json.enc` に暗号化され、インストールごとの鍵ファイル `data/.secret.key`（モード `0600` で作成）を使います。
- そのため、`data/` フォルダをコピーしたり同期したりしてもパスワードは漏れません。UI がパスワードを表示し直すこともないので、保存済みの値を保つにはパスワード欄を空欄にしてください。
- パスワードは**バックアップから除外されます**。

## バックアップ先

同じダイアログに **バックアップ先** が一覧表示されます。バックアップ先は、バックアップ ZIP のアップロード先です。

1. **バックアップ先を追加** で、ローカルフォルダ、ネットワークドライブ、WebDAV を選びます。
2. **この保存先へバックアップ** は `data/` の ZIP を作成し、そのバックアップ先の `backups/backup-<timestamp>.zip` にアップロードします。
3. 完了すると、対象、ファイル名、サイズが表示されます。

設定済みのソースとバックアップ先は **接続をテスト** で確認でき、オフラインのものは報告されます。

## 手動のバックアップと復元

- **バックアップを生成してダウンロード** は `data/` の ZIP を作成します。ページ、テンプレート、プリセット、レイアウト、`library.json`、`.backup-meta.json` を含みます。サムネイルキャッシュと一時ファイルは除外されます。
- **バックアップファイルを選択…** はまず ZIP を検査し、含まれるページ、ノート、テンプレート、プリセットの数と、対象の巻を報告します。
- 復元は `data/` の同名ファイルを**上書き**しますが、バックアップにないページは削除しません。復元の前に現在のデータのスナップショットが書き出されます。

ファイル単位の契約とストレージ JSON の正確な内容は、[リモート保存とバックアップ（リファレンス）](/ja/remote-backup) を参照してください。

## よくある落とし穴

- **リモートの巻が表示されない。** **リモートのフォルダツリーを同期** を実行してください。ライブラリがスキャンするのはミラーです。結果のファイル上限とスキップされたフォルダ数を確認してください。
- **すべてのページが 503 になる。** リモートがオフラインで、そのページが一度もキャッシュされていません。再接続してからページを開き直してください。
- **ディスク使用量が増え続ける。** キャッシュ上限は既定で 512 MB です。意図して引き上げるか、ライブラリを切り替えるときにキャッシュを消去してください。
- **バックアップにパスワードがない。** 仕様です。別のマシンで復元した後にパスワードを再入力してください。
- **ネットワークパスはエクスプローラーでは使えるのに、ここでは使えない。** ネットワークドライブは、アプリを実行するアカウントから到達できる必要があります。サービスや別のデスクトップユーザーで動かす場合に問題になります。
