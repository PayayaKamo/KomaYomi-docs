# リモート保存とバックアップ

## 現在存在するもの

ローカルディスクが既定です。KomaYomi は `raw/` から画像を読み、`data/` に注釈を書き、生成ファイルを `exports/` に書きます。その上で、サーバーは **リモート画像ソース** と **リモートバックアップ先** を WebDAV またはマウント済み／SMB のネットワーク共有経由でサポートします。**データツール → ストレージ** で設定し、`data/storage.json`（`schemaVersion: 1`）に保存されます。

さらに、持ち運べるローカルの安全網が2つ実装されています。

### リモート画像ソース（WebDAV / ネットワークドライブ）

種類が `webdav` または `network` のストレージターゲットを `rawSource` として設定できます。

- **構造同期** — **同期** はリモートツリーを走査し、そのフォルダ構成を `raw/` にゼロバイトのプレースホルダーファイルとしてミラーします（画像ファイルは最大 20,000 件）。既存のライブラリスキャナーと命名規則はそのまま機能し、プレースホルダーがどのページが存在するかを示します。
- **オンデマンド取得** — 画像のバイト列は、同期時ではなく、ページやサムネイルを初めて開いたときにダウンロードされます。取得したファイルは `data/cache/remote/files/` 以下に、プロバイダー id と相対パスの SHA-1 をアドレスとしてキャッシュされます。
- **LRU キャッシュ** — キャッシュは `cacheLimitMb`（既定 **512 MB**）で上限が決まります。書き込みのたびに、使用量が上限の **90%** を下回るまで、最も長く使われていないファイルから削除します。キャッシュはストレージ UI からクリアできます。
- **オフライン時** — キャッシュ済みのページは引き続き読めます。未キャッシュの画像は HTTP **503** とコード `ERR_REMOTE_UNAVAILABLE` を返し、サムネイルの取得失敗は **502** `ERR_THUMB_FETCH_FAILED` を返します。ライブラリはハングしたりページを黙って落としたりせず、ページを一覧し続けます。
- **認証情報** — ユーザー名は `storage.json` に保存され、パスワードは **AES-256-GCM** で `data/secrets.json.enc` に暗号化されます。インストールごとの鍵は `data/.secret.key`（モード `0600`）です。API は `hasSecret` のみを報告し、パスワードを返すことはありません。これは持ち運べるフォールバックであり、OS のキーチェーンではありません。データフォルダ全体を `.secret.key` と一緒にコピーした人は復号できます。
- **WebDAV の詳細** — Basic 認証、一覧と状態取得に `PROPFIND`、読み取りに `GET`、書き込みに `PUT`、リクエストタイムアウトは 10 秒です。読み取り専用のターゲットはソースとしては機能しますが、アップロードは拒否されます（`ERR_STORAGE_READONLY`）。

### バックアップ ZIP

- すべてのエントリに `data/` を前置し、`data/.backup-meta.json` マーカーを含む `data/` の ZIP を作成します。
- サムネイルキャッシュと `.tmp` / `.log` ファイルを除外します。
- ファイルは `exports/` に書き込まれ、ダウンロードとして提供されます。バックアップ先が選択されている場合、同じ ZIP がそのターゲットの `backups/backup-<timestamp>.zip` にアップロードされます。
- **復元前に検査** は、ファイル数、ページ数、ノート数、巻、テンプレート、プリセット、上書きされるファイル数、アーカイブのサイズを表示します。
- **復元** は `data/` 以下の同名ファイルを書き込みますが、バックアップにないページを削除はしません。何かを上書きする前に現在のデータのスナップショットが `exports/` に書き込まれるため、誤クリックも取り消せます。

### `.mnproj` プロジェクトパッケージ

`manifest.json`、ページ JSON、テンプレート、プリセットを含む ZIP で、2つのモードのいずれかです:

- **参照** — 画像のパスと SHA-1 ハッシュを記録します。小さい。画像が移動した場合、インポートは選択したフォルダからまずハッシュで、次にファイル名で**再リンク**できます。
- **パッケージ** — 重複排除した画像を `assets/<sha1>.<ext>` に埋め込みます。自己完結で持ち運べますが、大きくなります。

インポートの挙動:

- 最初に `data/` のスナップショットが書き込まれます。
- 元のパッケージは `data/backups/projects/` に保持されます。
- 競合は**上書き**、**マージ**、**スキップ**で解決できます。
- **マージ** は、入力側のページにコマ／注釈がない場合に既存のものを保持し、ノートを id で統合し、既存のノートを決して削除しません。

マニフェストのフィールドとフォルダ構成は [データ形式](/ja/data-format) を参照してください。

## 推奨される運用

1. **`raw/` は大きなローカルディスク**（または接続ドライブ）に置いてください。データの大部分を占め、gitignore の対象です。
2. **`data/` はバックアップ ZIP で定期的にバックアップ**してください。ほとんど JSON で小さく、作業のすべてが入っています。
3. 同じ画像を既に持つマシン間で注釈を移すには、**`.mnproj` の参照モード**を使ってください。
4. 自己完結したプロジェクトを他の人に渡すには、**`.mnproj` のパッケージモード**を使ってください。
5. 生成した学習ドキュメントを残したい場合は **`exports/` のコピーを保管**してください。gitignore の対象で、再生成できます。
6. 大きなライブラリは NAS 上の**リモートソース**を使ってください。オンデマンドキャッシュがローカルへの完全なコピーを避けつつ、閲覧の応答性を保ちます。

## 単にフォルダを同期するだけではだめなのか

`raw/`、`data/`、`exports/` をネットワークドライブや同期フォルダに置くことはできます。アプリはファイルをロックしませんが、書き込みはアトミック（`.tmp` + リネーム）なので、同期クライアントが書きかけの JSON を見る可能性は低いです。同じページを2台のマシンから同時に編集することは避けてください。最後の書き込みが勝ちます。

## 予定: まだないもの

以下は**実装されていません**。期待値を明確にするために記載します:

- <Badge type="warning" text="予定" /> **オフライン書き込みキュー** — 接続が切れている間は注釈とノートの書き込みをキューに入れ、再接続時に調整します。現在、書き込みは常にローカルの `data/` フォルダに行われ、リモートソースがオフラインのときに劣化するのは読み取りだけです。
- <Badge type="warning" text="予定" /> **スケジュールバックアップ** — ローカルまたは設定したターゲットへの自動の定期的スナップショット。
- <Badge type="warning" text="予定" /> **`data/` のバージョン履歴付きリモート同期** — WebDAV ターゲットは現在、画像を配信しバックアップ ZIP を受け取りますが、注釈データベース自体のバージョン管理は行いません。

それまでは、バックアップ ZIP、リモートバックアップのアップロード、`.mnproj` をサポート対象の転送手段として扱ってください。

## 復元チェックリスト

1. **バックアップ** をクリックし、ZIP が `exports/`（または選択したリモートターゲット）に現れることを確認します。
2. 復元するには **検査** を選び、件数を確認してから **復元** をクリックします。
3. 復元後、ライブラリを再読み込みします。注釈のあるページはサイドバーにバッジが付きます。
4. プロジェクトのインポートで画像が見つからないと報告された場合は、**再リンクディレクトリ** をそれらの画像を含むフォルダに向け、**マージ**で再度インポートします。
